# 01. Ansible ? 

## 1. 소개
- 여러 개의 서버를 관리하기 위한 환경 구성 자동화 도구 
- 2013년 버전 1 출시 이후 Red Hat에 인수됨 
- Chef, Puppet과 같은 구성 관리 도구의 일종이지만 사용성/확장성이 매우 뛰어남 
- 가본적으로 데이터 전송을 위해 `OpenSSH`를 사용
    - agnet 없이 서버 관리 가능 
- `yaml` 언어 사용

### 1-1. 예시 
- nginx config 수정
- 패키지 설치(apt install, yum install) linux user 생성/삭제
- sudo usergroup 관리
- 서버 종료 / 재부팅
- 파일 권한 변경

### 1-2. 기본 개념 
| 구분 | 설명 | 
|--|--|
| control node | ansible이 실행되는 노드(노트북, 서버) | 
| managed node | ansible이 관리하는 서버 | 
| inventory | managed node list | 
| module | ansible이 실행하는 코드 단위 |
| task | ansible 작업 단위, module의 모음 | 
| playbook | variable, task가 포함된 yaml 파일, host와 task를 연결 | 

## 2. 장・단점
### 2-1. 장점
1. 사용하기 편리함(단순함) = `yaml, ssh` 사용
2. downtime 없는 rolling update 지원 
3. ssh 사용(보안) = Agentless
4. kerberos / LDAP 와 같은 인증 관리 시스템과 연동 가능 
5. 변수 기능 사용으로 재사용성 높음 
6. 다양한 플랫폼 지원 = `ssh` 
7. **idempotency<sup>멱등성</sup>**

### 2-2. 단점
- 자체적인 기능이 다른 Tool에 비하면 적음 
- 자동완성이나 정적분석의 어려움 = yaml
- 변수 사용으로 복잡성 증가 = 변수 값 확인이 어려움 
- input, output, config 파일 간의 형식 일관성이 없음 가끔씩 성능 저하 발생
